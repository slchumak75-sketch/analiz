# Архитектура и передача следующему агенту

## Состояние проекта

Windows x64-приложение в одном EXE: локальный Python HTTP-сервер + интерфейс в стандартном браузере. Исходный XLSX проанализирован, но данные из него **не импортируются**; новая база пуста. Графики работают офлайн: vendored Chart.js 4.4.9 в `web/vendor/`, лицензия рядом. Изменения и решения владельца см. в [CHANGELOG](../CHANGELOG.md) и [decisions.md](decisions.md).

| Путь | Назначение |
|---|---|
| `app.py` | CLI, папка данных, запуск сервера/браузера, smoke test собранного EXE |
| `analiz/calculations.py` | Decimal-формулы квартала/года и проверки сумм |
| `analiz/store.py` | SQLite schema v1, транзакции, организации, статьи, кварталы, история, согласованная копия |
| `analiz/reports.py` | CSV с защитой пользовательских текстов от Excel formula injection |
| `analiz/server.py` | локальные HTTP endpoints, token/origin/Host, статические файлы |
| `web/` | HTML/CSS/JS, адаптивный интерфейс и локальный Chart.js |
| `scripts/audit_workbook.py` | воспроизводимая инвентаризация формул без финансовых значений |
| `scripts/ui-smoke.js` | браузерный end-to-end тест на временной базе, Chrome/Edge |
| `tests/` | тесты формул, всех 80 результатов книги, БД, HTTP и экспорта |
| `.github/workflows/build-windows.yml` | тестирование, Windows x64 сборка, smoke test EXE, артефакт |

## Расчётный контракт

Полный перечень всех 80 ячеек — [workbook-formulas.md](workbook-formulas.md), смысл и отличия — [workbook-analysis.md](workbook-analysis.md). `calculate_quarter` и `calculate_year` возвращают `Decimal`; JSON передаёт десятичные строки. Отображение округляет только на границе интерфейса; графики используют числовые приближения JavaScript и предназначены для визуализации, а не хранения сумм. Не подменять H15 суммой D15:G15 и не пересчитывать H17 через H15. Ставки всегда 20%, налог на прибыль при убытке не обнуляется.

Поля ввода ограничены 18 цифрами до и 8 после запятой, отрицательные значения разрешены; семь основных полей обязательны, пустые расходы равны нулю. Нет вычисления или интерпретации метки C. Все дополнительные категории суммируются в квартальный и годовой расход. Чистая рентабельность использует выручку без НДС и не определяется при неположительной базе. Изменение к прошлому году считается только для совпадающего набора сохранённых кварталов, при положительном предыдущем показателе; неполные годы на графике помечаются `n/4`.

## База и транзакции

`%APPDATA%/AnalizOrganizaciy/analiz.sqlite3` в Windows; `--data-dir`/`ANALIZ_DATA_DIR` для изолированных тестов. Схема `PRAGMA user_version=1`: `organizations`, `categories`, `periods`, `expenses`. Денежные значения — TEXT с нормальной десятичной записью, `FOREIGN KEY` и триггеры не допускают смешивания организаций. Сохранение квартала — атомарный `BEGIN IMMEDIATE`; чтение сводки — согласованный read transaction. Категория архивируется, а не удаляется; отсутствующие в старой форме архивные значения не стираются.

Резервная копия создаётся через SQLite online backup API и включает WAL. Ручное восстановление описано в README; CSV не является форматом восстановления. Любую миграцию делать обратимо, с тестами и предупреждением о резервной копии; более новая неизвестная версия базы не должна открываться старым приложением.

## Безопасность и HTTP

По умолчанию сервер слушает только `127.0.0.1` на случайном порту. Все `/api/*` кроме health требуют случайный токен в `X-Analiz-Token`; запись дополнительно проверяет `Origin`, local-only режим ограничивает Host (защита от DNS rebinding), CORS не разрешён, запросы ограничены 1 МиБ, статические пути — allowlist, в обычном режиме запрещён iframe. Финансовые данные не логируются и не передаются наружу. HTML получает токен при открытии; JavaScript экранирует пользовательские строки.

`--host 0.0.0.0` — только для защищённого предпросмотра; в нём проверка loopback-Host и запрет iframe намеренно отключены. Токен по-прежнему обязателен, но режим не предназначен для опубликования реальных данных. Внешних CDN, API и сетевых вызовов в интерфейсе нет. Закрытие вкладки не останавливает процесс; используйте кнопку завершения.

Главные API: `GET /api/organizations`, `/api/categories`, `/api/period`, `/api/summary`, `/api/report.csv`, `/api/backup`; `POST /api/organizations`, `/api/categories`, `/api/period`, `/api/shutdown`; `PATCH /api/organizations`, `/api/categories`; `DELETE /api/organizations`, `/api/period`. Идентификаторы статей проверяются на принадлежность организации. Эти API внутренние, не предназначены для удалённого использования.

## Проверка и сборка

```bash
python -m pip install -r requirements-dev.txt -r requirements-build.txt
python scripts/audit_workbook.py --check
python -m pytest -q
npm ci
npm run test:ui
python app.py --self-test
```

Для UI-теста на Linux укажите `CHROME_PATH`, если браузер не найден автоматически. На Windows runner используется установленный Chrome/Edge. Тесты используют временные базы и синтетические числа, но контрактные тесты читают исходный XLSX для сравнения сохранённых результатов всех формул.

Windows-сборка: `python -m PyInstaller --onefile --windowed --name AnalizOrganizaciy --add-data "web;web" app.py`. Workflow запускается на каждом push, проверяет исходник/тесты/UI/EXE и публикует `AnalizOrganizaciy-Windows-x64`. Артефакт GitHub хранится 90 дней и не является релизом. Локальный commit без push не запускает GitHub Actions.

## Что остаётся на будущее

- Импорт XLSX, назначение исходным суммам года/организации и настройка ставок сознательно **не реализованы** по решению владельца; сначала получите новое подтверждение.
- Ставки, бухгалтерский смысл отрицательного налога и столбца C не были юридически подтверждены. Не исправляйте их по предположению.
- Если будет предоставлена другая книга или изменится шаблон, отдельно сверить формулы и реальные значения, обновить анализ/инвентаризацию/контрактные тесты и только затем менять код. Не переписывайте fingerprint для прохождения CI без исследования.
- Будущие улучшения интерфейса, экспорта и миграций должны сохранять существующие данные и сопровождаться тестами, changelog и документацией. Не коммитьте рабочие базы/резервные копии и не публикуйте дополнительные копии финансовых данных.
