# Архитектура и передача следующему агенту

## Состояние проекта

Windows x64-приложение в одном EXE: локальный Python HTTP-сервер + адаптивный интерфейс в стандартном браузере. Четыре квартала, годовой итог, анализ и единственный график структуры затрат находятся на одной странице. Новая база пуста; импорт исходной или своей книги выполняется только после явного подтверждения организации/года и режима замены. Графики работают офлайн: Chart.js 4.4.9 в `web/vendor/`, лицензия рядом. См. [CHANGELOG](../CHANGELOG.md) и [решения владельца](decisions.md).

## Расчётный контракт

Полный перечень 84 ячеек актуальной книги — [workbook-2-formulas.md](workbook-2-formulas.md); прежние 80 — [workbook-formulas.md](workbook-formulas.md), особенности — [workbook-analysis.md](workbook-analysis.md). `calculate_periods`, `calculate_quarter` и `calculate_year` возвращают `Decimal`; JSON передаёт десятичные строки. Округление — только на границе интерфейса; графики используют числовые приближения JavaScript. Не подменять H15 суммой D15:G15 и не пересчитывать H17 через H15. Общие константы формул НДС и налога на прибыль всегда 20%; отрицательный налог не обнуляется. Формулы D15:G15 накопительные и действуют для всех лет; `None` означает ошибку деления на ноль, которая распространяется по зависимостям, включая H4/H17. H15 при этом может быть определён независимо.

Поля ввода: до 18 цифр до и 8 после запятой, отрицательные значения разрешены; шесть основных полей обязательны для заполненного квартала, пустые расходы равны нулю. Ставки НДС статей (C, включая 25% в C31) подтверждены владельцем, отображаются и задаются отдельно на каждый год, но не участвуют в формулах: общий входящий НДС вводится вручную. Все дополнительные категории входят в квартальные и годовые итоги. Чистая рентабельность использует выручку без НДС и не определяется при неположительной базе. Изменение к прошлому году считается по совпадающим кварталам при положительном предыдущем значении; несохранённые кварталы не подменяются сохранёнными нулевыми.

`period_analysis`: себестоимость продаж — переменная; остальные статьи пользователь размечает как `fixed`, `variable`, `unclassified`. Порог = `fixed / ((revenue_without_vat - variable) / revenue_without_vat)`. Ненулевые неразмеченные затраты, неположительные выручка/маржинальный доход или отрицательные постоянные затраты блокируют порог. Положительный/отрицательный запас — фактическая выручка без НДС минус порог. Неразмеченные суммы нельзя выдавать за полные фиксированные/переменные затраты. Это модель текущей структуры, не налоговый совет или прогноз.

`expense_structure`: для каждого квартала сохраняются `quarter_amounts`, `quarter_share_percent` и статус знаменателя; годовая структура используется в отчёте Excel. Знаменатель — все статьи, НДС к уплате и налог на прибыль без себестоимости реализации; при неположительном знаменателе или неопределённом НДС доля недоступна, знак сохраняется. Единственный график страницы использует **quarter_amounts**, а не доли: даже при отрицательном итоге или неопределённом НДС другие доступные суммы не исчезают. Неизвестный НДС и отсутствующие кварталы — пропуски. По явному решению владельца ось и подсказки всегда подписаны «руб.» без конвертации, даже если организация настроена в другой единице; настройки и данные не изменяются. Слева только названия статей и налогов, архивные суммы включены. Изменять правила прибыли и безубыточности ради графика нельзя.

Пять панелей сворачиваются кнопками с `aria-expanded`; их состояние хранится в localStorage браузера. Скрытые элементы формы остаются в DOM и входят в сохранение. Таблицы без горизонтальной прокрутки: на широком экране колонки ужимаются, на узком строки преобразуются в поля с подписями каждого квартала. Меню статьи открывается наведением на её название, нажатием или с клавиатуры, не забирая фокус при наведении; касание поддерживается отдельно.

## База и транзакции

В Windows база — `%APPDATA%/AnalizOrganizaciy/analiz.sqlite3`; `--data-dir`/`ANALIZ_DATA_DIR` позволяют изолировать тесты. `PRAGMA user_version=3`: таблицы `organizations`, `categories`, `periods`, `expenses`, `category_year_settings`; стабильный `export_key` сопоставляет статьи при XLSX roundtrip. Схемы v1 и v2 мигрируются транзакционно; старый ручной `periods.non_vat_deduction` копируется в nullable `legacy_manual_deduction` и сохраняется справочно. Новые периоды не получают ложной истории; пересохранение периода её не стирает. Схема создаётся/мигрируется под блокировкой `BEGIN IMMEDIATE`, в том числе при одновременном запуске окон; при кратковременной блокировке WAL выполняется ограниченный повтор. Сначала полезно сохранить резервную копию, прежний EXE не открывает новую схему. Неизвестные текстовые метки из v1 сохраняются, но не угадываются как ставки.

Денежные значения — десятичный TEXT; `FOREIGN KEY` и триггеры не допускают смешивания организаций. Годовая запись и импорт используют `BEGIN IMMEDIATE` и атомарно сохраняют все периоды/настройки. Чтение сводки — согласованный read transaction. Сводка содержит SHA-256 ревизию данных года и статей; сохранение, подтверждение импорта и создание статьи при наличии черновика повторно проверяют её внутри транзакции и отклоняют устаревшие данные из другого окна. Предпросмотр формирует снимок без записи; незавершённый квартал исключается из расчётных итогов и явно помечается. У каждой статьи меню с действиями скрытия/удаления, в архиве — восстановления/удаления. Архивная статья скрыта из ввода, но сохраняет суммы во всех годах и может быть восстановлена. Безвозвратное удаление — отдельное действие: `/api/category-impact` перечисляет все годы, кварталы и настройки, а DELETE требует явного подтверждения и SHA-256 ревизии воздействия, проверяемой внутри транзакции. При конкурирующей правке удаление отклоняется.

Резервная копия создаётся SQLite online backup API и включает WAL. Ручное восстановление описано в README; CSV не является форматом восстановления. Любую новую миграцию сопровождать тестами и предупреждением; старая версия не должна открывать более новую схему.

## Обмен Excel

`make_report()` формирует `Лист1` с теми же исходными вводами/формулами, дополнительными статьями, столбцом типа затрат, лист `Аналитика` со значениями и двумя диаграммами, а также скрытые стабильные идентификаторы и прежние ручные вычеты в метаданных `ANALIZ_XLSX_V3`. В книге включён автоматический перерасчёт формул при открытии; аналитика и диаграммы — отмеченный в книге снимок, после правок нужен повторный импорт/экспорт. Новые строки вне диапазона формул также учитываются после повторного экспорта. `parse_report()` принимает обе исходные книги и собственные книги V2/V3, читает **только входные значения**, не исполняет формулы и не доверяет их кэшированным результатам. Формулы во входах, макросы, внешние связи, повреждённые/неоднозначные привязки и неподдерживаемые XLSX отклоняются. Пустой квартал не считается заполненным; для вычисления квартальных формул его значения приравниваются к пустым ячейкам Excel. Прежний числовой D15:G15 сохраняется как история и не становится новым входом.

На ввод: до 10 МиБ ZIP, 80 МиБ распакованного содержимого, 1500 файлов архива, 1020 строк и 1000 статей; XML защищён `defusedxml`. Read-only лист читается за один проход, а не многократными `.cell()`. Идентификаторы своего отчёта проверяются по названию; новые статьи допустимы в конце. Исходные статьи сопоставляются по номеру/названию, новые без ключа — по названию и ставке при однозначности. Дубликаты и конфликтные идентификаторы отклоняются, а не угадываются.

Excel хранит 15 значащих цифр: экспорт отменяется с понятной ошибкой, если входное значение может потерять точность. Вычисленные значения на листе аналитики/графиках являются приближением Excel; точная резервная копия — SQLite. Предпросмотр импорта ограничен тремя временными записями в памяти на 10 минут, привязан к выбранным организации и году; запись выполняется только с одноразовым токеном, явными `replace_existing` и `apply_settings`. Последняя настройка действует на весь год, даже на кварталы, не входящие в импорт. При её применении исходный файл без типов не стирает существующую классификацию. Замена квартала заменяет все статьи, в том числе архивные; кварталы вне файла не удаляются.

## Безопасность и HTTP

По умолчанию сервер слушает только `127.0.0.1` на случайном порту. Все `/api/*` кроме health требуют случайный `X-Analiz-Token`; запись дополнительно проверяет Origin, local-only режим ограничивает Host (DNS rebinding), CORS не разрешён, обычный JSON ограничен 1 МиБ, XLSX — 10 МиБ. Статические пути перечислены явно; в обычном режиме запрещён iframe. Финансовые данные не логируются и не передаются наружу. HTML получает токен при открытии; JS экранирует пользовательские строки.

`--host 0.0.0.0` — только для защищённого предпросмотра; loopback-Host и запрет iframe намеренно отключены. Токен обязателен, но режим не предназначен для публикации реальных данных. Интерфейс не использует внешние CDN/API. Закрытие вкладки не останавливает процесс; используйте кнопку завершения.

Основные API: `GET /api/organizations`, `/api/categories`, `/api/category-impact`, `/api/period`, `/api/summary`, `/api/report.csv`, `/api/report.xlsx`, `/api/backup`; `POST /api/year/preview`, `/api/year`, `/api/excel/preview`, `/api/excel/import`, `/api/organizations`, `/api/categories`, `/api/period`, `/api/shutdown`; `PATCH /api/organizations`, `/api/categories`; `DELETE /api/organizations`, `/api/categories`, `/api/period`. Это внутренние локальные API, не предназначенные для удалённого использования. Идентификаторы статей проверяются на принадлежность организации.

## Проверка и сборка

```bash
python -m pip install -r requirements-dev.txt -r requirements-build.txt
python scripts/audit_workbook.py --check
python -m pytest -q
npm ci
npm run test:ui
python app.py --self-test
```

Для UI-теста на Linux укажите `CHROME_PATH`, если браузер не найден автоматически. Windows runner использует установленный Chrome/Edge. Тесты работают с временными БД и синтетическими значениями; контрактные тесты читают оригинальный XLSX для сравнения всех 84 сохранённых результатов формул актуальной книги; отдельно проверяется, что в старой книге отличались только D15:G15.

Windows: `python -m PyInstaller --onefile --windowed --name AnalizOrganizaciy --add-data "web;web" app.py`. `requirements.txt` с runtime-зависимостями должен быть установлен до сборки. Workflow запускается на каждом push, проверяет формулы/тесты/UI/EXE и публикует `AnalizOrganizaciy-Windows-x64` на 90 дней. Используются закреплённые версии официальных Actions v7 на Node.js 24. Артефакт не является релизом; локальный commit без push не запускает Actions.

## Для будущих изменений

- Если предоставлена другая книга или изменился шаблон, отдельно сверить формулы/значения, обновить инвентаризацию и контрактные тесты; не менять fingerprint вслепую.
- Не делать правовых предположений об отрицательном налоге и не менять правила ставок без решения владельца.
- Сохранять совместимость данных и покрывать интерфейс, импорт, миграции и сборку тестами; не коммитить базы/копии и не публиковать новые финансовые данные.
