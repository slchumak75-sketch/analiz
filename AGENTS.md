# Инструкции следующему агенту

1. Начните с [README](README.md), [решений владельца](docs/decisions.md), [анализа книги](docs/workbook-analysis.md) и [архитектуры](docs/architecture.md). Если требования или бухгалтерский смысл неясны — **спросите владельца**, не угадывайте.
2. Не назначайте исходным суммам год/организацию и не добавляйте импорт XLSX без нового решения владельца. Ставки 20% фиксированы. H15 и H17 должны точно следовать исходной книге, включая деление на ноль и возможный отрицательный налог.
3. Не считайте неизвестную метку C ставкой НДС. Не публикуйте введённые финансовые данные, SQLite-базы или резервные копии. Книга уже есть в публичном репозитории; дополнительных копий не создавайте.
4. При изменениях сохраните совместимость данных и покройте её тестами. Проверьте `python scripts/audit_workbook.py --check`, `python -m pytest -q`, `npm ci && npm run test:ui`, `python app.py --self-test`. UI-тест использует Chrome/Edge и временную БД.
5. Если книга изменилась, сравните все формулы и зависимости до обновления её fingerprint или генерации `docs/workbook-formulas.md`; не меняйте их вслепую ради зелёного CI.
6. Обновляйте `CHANGELOG.md` и релевантную документацию после каждого заметного изменения. GitHub Actions автоматически проверяет каждый push и собирает Windows x64; проверяйте результат запуска и артефакт. Работайте в назначенной пользователем/системой ветке, не предполагайте, что можно писать в `main`.
